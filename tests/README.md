## 未涵蓋清單＋原因

以下內容**刻意不寫自動化測試**，因為規則模糊、需要語意判讀，或本來就是「隨堂互動決定」而非資料能唯一推出的答案：

- **2-1**：Step2 的家長信草稿本文、Step5／Step6 的批次產出表格（只列少數範例＋`...`佔位，課文本身沒有宣稱窮舉，不構成可機器判定的一致性主張）——不測。已測的部分只有其中嵌入的具體成績數字。
- **3-2**：常見問題處理裡「9 位家長、佔 32%」這個語意分類數字（要判斷哪些開放式留言算「不透明／不確定」需要人工判讀語意，不是關鍵字比對能穩定重現的規則）——不測。已用生成式關鍵字比對手動核對過一次，9/28≈32% 算得出來，但這個判讀本身就是模糊的，寫死關鍵字清單去測反而會製造假的「機械客觀」錯覺，所以刻意不寫。
- **3-4**：Step4 轉化率表的「入學人數」「轉化率」兩欄——這兩欄的數字依賴 Step3 那 3 組模糊姓名配對（王小明/王小名、李美玲/李玫玲、陳建宏（？））怎麼解讀，而 Step3 的 Check 明講「等學生說出確認結果（無論是哪種回答都繼續）」，代表這堂課的設計本來就是「答案由老師當場決定」，資料本身無法唯一推出這兩欄該是多少。只測了不依賴這 3 組模糊配對的部分（報名人數、確定入學／未入學名單、需要確認的姓名清單）。

## 核對出的不一致（第 1 步人工核對逐項列出）

### 1-1：已知問題，規則算出四人、示範表格只寫兩人

課文 Step2 規則：「找出三次月考都在下滑的學生」（三次月考嚴格遞減）。
Step3 規則：「家長滿意度 3 分以下、或留言明確講到負面狀況的」，疊加在成績下滑名單上。

用 `exam-scores.csv` 算出成績連續下滑的學生有 10 位：S002、S003、S006、S008、S009、S012、S014、S017、S019、S025。

用 `parent-survey.csv` 對照這 10 位裡「滿意度 ≤3 或有留言」的：

| 學號 | 姓名 | 滿意度 | 留言 | 是否命中 |
|------|------|--------|------|---------|
| S002 | 黃志明 | 4 | 「希望多練習口說」 | 有留言 → 命中 |
| S006 | 吳佩珊 | 4 | 「希望老師多關注」 | 有留言 → 命中 |
| S008 | 吳建宏 | 3 | 「家裡最近有些狀況，孩子可能受影響」 | 滿意度≤3＋有留言 → 命中 |
| S019 | 張志豪 | 2 | 「擔心孩子上課心不在焉，成績也在走下坡」 | 滿意度≤3＋有留言 → 命中 |
| 其餘 6 位（S003/S009/S012/S014/S017/S025） | — | 4 | 空白 | 未命中 |

**規則算出來是 4 位（S002、S006、S008、S019），但 SKILL.md Step3「本週優先關注」的示範表格只寫了 2 位（S008、S019），漏了 S002 和 S006。** 這兩位在課文邏輯裡屬於「有留言但沒有明確負面字眼」（「希望多練習口說」「希望老師多關注」比較像請求而非示警），如果 Dustin 想把規則收窄成「留言內容要明確負面」而不是「只要有留言」，S002/S006 被排除就是對的，只是這樣的話課文裡「或留言明確講到負面狀況」這句話需要更精確定義「明確負面」是什麼，目前的文字寫法讓一個機械規則（有留言＝命中）跟一個語意規則（負面留言＝命中）算出不同答案，這正是 4 vs 2 的根源。**這個判準本身要 Dustin 拍板，我沒有替換或修改示範表格。**

### 2-1、2-3、3-1、3-2：核對後皆一致，未發現差異

- 2-1：張志豪 63→60→55→53、林子晴 88→90→91→93 兩處引用文字，以及 `priority-watchlist.csv` 三筆摘要裡的趨勢數字，都跟 `exam-scores-oct.csv` 一致。
- 2-3：男生 13 位、候選名單 {S008, S019, S024}（性別男 + 出席率三月嚴格遞減）、各自百分比、吳建宏摘要，都跟 `student-roster.csv`／`attendance.csv` 一致。
- 3-1：三張表是資料的原樣照抄，逐格比對後完全相同。
- 3-2：量化評分表跟 CSV 一致；28 份 = 明細 12 筆 + 其餘 16 份，加總對得上，且與 Step1 引用的「28 份」一致。

### 3-4：核對後未發現硬性不一致，但有一個邏輯瑕疵觀察（未寫進測試）

已測部分（報名人數、確定對應／未入學名單、需要確認姓名清單）全部一致。

觀察到的瑕疵：課文常見問題處理寫「如果電話號碼一樣，我的判斷信心高；如果電話不同，我就說不確定」。
但實際資料裡，王小明（0912-100-001）跟王小名（0912-100-009）電話不同，李美玲（0912-100-002）跟李玫玲
（0912-100-010）電話也不同——兩組電話都不同，可是 Step3 對前一組的「我的判斷」給的是「可能是兩個不同人」，
對後一組卻給「可能是同一人，名字寫錯」。兩組條件相同（電話都不同），結論卻不同，跟 FAQ 講的判斷依據對不上。
這不影響已測的部分（報名人數／已確定入學名單），但如果之後有人想把 Step4 轉化率表的「入學人數」也自動化，
會直接撞到這個瑕疵，先記在這裡供 Dustin 判斷要不要修課文。

## 反驗紀錄

沒有 Bash 工具可以實跑，以下改用逐行推演：對每個 check 函式，① 用現況資料推演一次應該通過或失敗、
② 假想把某一筆 CSV 資料改掉，推演該 check 會不會叫。

**推演過程中抓到並修掉一個真會誤報的 bug**：`check_3_2` 一開始直接用
`len(parse_md_table(comments_text))` 當作「明細留言筆數」，但 `parent-survey-comments.md`
最後一行「`|（其餘 16 份填答較簡短，均給正面評分）| |`」開頭也是 `|`，會被 markdown table parser
誤判成第 13 筆真實資料列，導致明細筆數算成 13，13+16=29 ≠ 28（標題寫的份數），在完全沒有任何實際
資料錯誤的情況下就會誤報。修法：只把「家長」欄位是單一字母（A、B、C…）的列算進明細筆數，排除掉那行
不是資料、只是說明性質的備註列。修完後乾淨資料下正確算出 12 筆，12+16=28，不再誤報。

| Check | 現況資料推演 | 假想改一筆資料後的推演 |
|-------|------------|---------------------|
| `check_1_1` | 規則集合 {S002,S006,S008,S019} ≠ 表格集合 {S008,S019} → 回報不一致 → **FAIL（預期，已知問題）** | 把 S008 的滿意度從 3 改成 4、留言清空 → 規則集合掉成 {S002,S006,S019}，跟表格 {S008,S019} 的差異換了內容，但仍然不相等 → 仍然 **FAIL**，訊息內容會變（驗證 check 對資料變動有反應，不是卡死輸出同一句話） |
| `check_2_1` | 兩處文字引用與三筆摘要數字都跟 CSV 相符 → **OK** | 把 `exam-scores-oct.csv` S019 的月考一從 63 改成 65 → SKILL.md 文字仍寫 63，`cited != oct_scores["S019"]` → **FAIL** |
| `check_2_3` | 男生 13 位、候選名單三人、各自百分比、吳建宏摘要都相符 → **OK** | 把 `attendance.csv` S024 第二月從 84% 改成 95%（打斷遞減）→ `declining_males` 少了 S024，但表格仍列 S024 → 集合不相等 → **FAIL** |
| `check_3_1` | 三張表逐格比對全部相同 → **OK** | 把 `zhang-zhihao-scores.csv` 月考成績第二月從 60 改成 61 → 表格仍寫 60，`actual != expected` → **FAIL** |
| `check_3_2` | 量化表相符、修完 bug 後 28=12+16、Step1 引用一致 → **OK** | 把 `parent-survey-comments.md`「其餘 16 份」改成「其餘 15 份」→ 12+15=27≠28 → **FAIL** |
| `check_3_4` | 欄位對照、報名人數、確定對應／未入學名單、需要確認姓名清單全部相符 → **OK** | 把 `trial-class-registrations.csv` 其中一筆「口碑介紹」的來源改成「FB廣告」→ 口碑介紹報名人數變 4（表格仍寫 5）、FB廣告變 5（表格仍寫 4）→ **FAIL**；另外把 `enrolled-students.csv` 刪掉許佳玲那一列 → 她從「確定入學」變成「完全沒出現在入學名單」，未入學名單規則算出多一人、表格沒改 → **FAIL** |

乾淨資料（現況）下五堂（2-1、2-3、3-1、3-2、3-4）都不誤報，1-1 正確抓到已知問題；每個 check 在假想的破壞案例下都會叫。除了上面記錄的 3-2 那個已修掉的誤報，沒有再發現其他「乾淨資料下就誤報」或「破壞案例測不出來」的情況，反驗通過。

### 2026-09-16 實跑補記（夜批主線，非推演）

上面那段是**推演**結果，實跑後有一項被推翻，記錄如下：

- **`check_3_4` 在乾淨資料下其實會誤報**：`table_confirmed_enrolled` 的迴圈條件寫成
  `if r is not_enrolled_row:`（應為 `is not`），把「已入學」五列全部略過、反而只收「未入學」那一列，
  於是乾淨資料下就叫。已改成 `is not`，改完實跑 3-4 轉為 OK。這正是推演式反驗看不出來的那類錯。
- **實跑結果**：`bash tests/run.sh` → exit 1，只有 1-1 一筆不一致（＝已知教材問題），其餘五堂 OK。
- **破壞案例實測（in-memory 改資料、未動 assets）**：改 S008 的 `attendance.csv` 第三月 → 2-3 叫出
  候選名單與 Step4 摘要兩筆；把 S001 性別改成男 → 2-3 叫出「男生 13 位 vs 實際 14 位」。確認 check 會動。
